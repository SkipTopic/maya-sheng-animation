# 从真实 Maya 动画项目提炼的强制规则

## 1. 人物模型

真实项目曾出现局部 `Spine.rotateX` 很小、世界躯干却前倾约 45° 的情况。由此得到：

- 局部欧拉角不能替代世界姿态。
- 原始 FBX 的中立变换比“全部归零”可靠。
- 人物组的落座补偿不能随意清零。
- 骨架、蒙皮网格和父级变换必须一起核对。

## 2. 自动绑定和姿态

此前流程把绑骨、摆姿、动作和相机快速连在一起，导致无法判断错误来自哪一层。由此得到：

- 绑定后先做标准姿态，不立即做正式动画。
- 旧 MMD 大角度弯臂破袖时，区分蒙皮结构与姿态算法。
- 新模型导入前先统计 morph 和总顶点数。
- 姿态失败时调用专门修复 Skill，不在动画阶段硬补。

## 3. IK 和动画

真实测试中 IK 手柄到达目标，脚踝却没有到达。由此得到：

- 读取实际末端位置。
- 显式指定两段 IK 的中间关节。
- 不混淆 twist 骨。
- 记录目标是否被钳制。
-  Maya 行向量约定下世界增量旋转使用 `old_q * delta`。
- 保存后重开再测一次。

## 4. 相机

旧项目有 71 台相机，但只有 12 种位置/朝向；另一轮还出现图片文件名不同而内容完全相同。由此得到：

- 相机数量不是切镜证据。
- 必须保存实际创建名称。
- 切换当前可见面板并执行 lookThru。
- 检查图像哈希和真实画面。
- 分镜必须包含前景、视线、轴线和承接，不是只有主体和景别。

## 5. 动作范围

用户允许“头部和手部”时，分镜中的站起、坐回和大幅前倾不能自动变成全身动画。由此得到：

- 将允许、禁止和待确认动作写入任务简报。
- 不执行嘴型或手指时，保持其通道不动。
- 复杂道具动作先检查实际道具数量。
- 不用统一模板或 root 摇摆冒充表演。

## 6. 序列和编码

历史流程曾出现首末两帧被误当区间、旧目录混帧、24fps 写死、无音轨和假通过。由此得到：

- 每镜立即检查 `end-start+1`。
- 使用新版本目录。
- 按数字帧号排序。
- 不用切片截断隐藏多出帧。
- 编码核对帧率、帧数、时长和音轨。
- 抽取切点和动作帧做视觉复核。

## 7. 验收与诚信

历史自查曾只检查容易通过的指标，漏掉人物可见性、静止图、穿模和闪面。由此得到：

- 区分节点存在、参数正确、渲染生效和视觉通过。
- 每个阶段都有停止门槛。
- 未确认静帧和短段时不渲全片。
- 不将中间试验版称为最终版。
- 报告必须写遗留问题，不只写成功。

## 8. 不复制案例数值

以下只适用于原案例，不能硬编码到新项目：

- 具体人物位置和桌面高度。
- 髋部 54/58cm 等补偿。
- 具体骨名、局部角度和目标坐标。
- 71 镜、3512 帧。
- 854×480 预览分辨率。
- 禁止嘴型和手指的项目约束。

复制方法和验收逻辑，重新测量新项目。
